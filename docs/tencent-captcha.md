# 腾讯云人机验证

腾讯云验证码用于减缓自动化滥用。客户端取得的票据只作为输入，放行决定由服务端向腾讯云核验后作出。

## 接入场景

- 发送邮箱或短信验证码：使用普通验证码；服务端核验成功后才调用邮件或短信供应商。
- 注册、登录和密码找回：使用无感验证；服务端检查票据、风险结果及请求上下文。
- 登录的双重验证窗口：第一阶段确认主凭据后，如账号启用 TOTP，再在独立窗口核验第二因子；该步骤不会以客户端标记代替服务器校验。
- 账号安全窗口、改密确认和 Authenticator 设备确认：在发码或确认动作前执行相应验证，最终仍由服务端检查一次性许可与账号状态。

人机验证不是账号认证，不代表验证码已发送，也不能代替邮箱、手机号、密码或 TOTP 的业务校验。

## 配置

环境模板中的配置项：

    CAPTCHA_ENABLED
    CAPTCHA_NORMAL_APP_ID
    CAPTCHA_NORMAL_SECRET
    CAPTCHA_INVISIBLE_APP_ID
    CAPTCHA_INVISIBLE_SECRET
    TENCENT_CAPTCHA_SECRET_ID
    TENCENT_CAPTCHA_SECRET_KEY

系统管理员可在全站配置中心维护应用 ID 和服务端密钥。真实凭据不得写入源代码或截图。建议为服务端核验配置权限受限的云 API 子账号，并在腾讯云控制台配置正确的业务域名。

当前站点的人机验证开关是运行时配置；请以登录/注册界面及服务端健康检查为准，不要假设本地模板值等于线上状态。

## 服务端安全要点

1. 客户端票据必须提交到业务服务端，再调用腾讯云票据校验 API。
2. 服务端按验证场景选用对应应用配置，并以可信代理来源确定请求 IP。
3. 只接受腾讯返回的成功状态与满足策略的风险等级；过期、错误、高风险、重复或缺失票据均应拒绝。
4. 验证通过后使用短时、一次性许可绑定账号、会话版本、动作及请求来源；业务接口仍需重新验证授权。
5. 限制票据校验频率并避免将票据、密钥和验证码写入日志。
6. 云端配置缺失或校验服务不可用时，应返回明确失败，不静默跳过校验。

## 验收方法

- 发送验证码前未完成人机验证时，验证码服务不应被调用。
- 错误、过期、重放和高风险票据应被拒绝。
- 直接请求业务 API 不能绕过人机验证许可、账号认证或二次验证。
- 对外展示供应商“成功”时，需通过真实浏览器产生票据并由服务端核验；单元测试或无效票据诊断不能替代此项实测。
