# CampusPulse AI 技术说明

更新日期：2026 年 11 月 10 日

## 1. 项目简介

CampusPulse AI 是面向高校社团与校园组织的双语运营数据工作台。它将表格、活动图片与团队复盘连接成一条可核验流程：导入资料、检查数据、使用 AI 辅助分析、制作图表与报告，再把建议整理成团队任务。

项目以 Web 应用为核心，不要求用户安装专用桌面软件。系统支持多空间协作和服务端资源授权。示例环境使用原创合成数据，不包含真实学生资料。

## 2. 目标与设计原则

1. 让活动运营资料能以结构化记录保存并追溯来源。
2. 将模型生成的解释与程序计算的数值分开，降低统计错误。
3. 限定 AI 访问用户当前有权限的数据集和字段。
4. 让图表、报告和行动项关联到可复核的数据。
5. 将账号和平台配置与普通空间权限隔离。

## 3. 系统架构

浏览器使用 Next.js App Router 和 React 构建交互界面。Route Handlers 负责输入验证、登录态、空间角色和资源授权。Prisma 管理 PostgreSQL 业务记录；原始表格及图片放在私有 S3 兼容存储中。AI、邮件、短信、人机验证和 OAuth 通过服务端适配器连接外部服务。

主要领域对象包括用户、空间、成员关系、数据集、来源证据、分析记录、图表、报告版本、任务、知识卡、平台配置及审计事件。具体模型以 prisma/schema.prisma 为准。

## 4. 数据导入与证据

导入服务校验文件类型、大小、编码、表头及记录限制，再解析表格内容并生成字段字典。图片通过可用视觉模型或 OCR 引擎读取，系统保存原文件与识别证据，并验证结构化结果。

当提取内容包含表格明细时，将明细展开为多行记录；否则保留为单行字段。嵌套对象需归一化后方可用于表格、统计和图表，避免出现对象默认字符串。用户可在详情页同时检查结构化记录和原始识别内容。

## 5. AI 分析流程

1. 用户选择数据集并提交问题。
2. 服务端确认账号、空间成员关系、数据集归属和可用字段。
3. Agent 获取受限的数据画像和上下文，选择当前场景允许的工具。
4. 工具在服务端执行过滤、聚合、比率、异常候选或证据读取。
5. 模型基于工具结果组织自然语言解释。
6. 保存分析与工具轨迹，便于后续查看和复核。

模型服务采用 OpenAI-compatible Chat Completions 接口；模型名称和连接参数由运行环境或管理员配置。工具执行受限于当前数据集，禁止跨空间查询。统计值由程序计算，模型不能代替数据计算。

## 6. 确定性工具与知识检索

求和、计数、平均和比率基于解析后的记录计算；比率必须显式提供不同的分子、分母字段，可按类别分组，并报告无法计算的行。比率只是算术结果，系统不推断字段的业务语义；称为转化率等业务指标前，必须根据字段定义核实分子与分母兼容。异常分析以中位数和 MAD 进行稳健候选筛查，至少需要 5 个有效数值；候选项仍需人工核对，不代表已证实错误。

项目知识来自维护在应用内的知识卡，通过词项相关度排序。没有达到相关门槛的问题不应返回无关知识。当前实现不使用向量数据库，未提供文档向量化或自动知识更新，不实现 MCP 协议。以上能力边界必须与代码现状保持一致。

## 7. 可视化、报告与协作

图表保存时关联空间和数据集。前后端都应按照当前选择的数据集过滤图表，避免不同来源字段不匹配。推荐图表可由用户导入画布，进一步编辑、保存和导出。

报告通过服务端生成并支持编辑和版本记录；任务用于团队后续跟进。报告内容和行动建议仍需用户核验，不能把生成内容当作实际执行结果。

## 8. 身份认证与安全

系统支持密码及已配置的邮件/手机认证，并可启用 TOTP 和一次性恢复码。敏感账号操作需要当前已绑定验证方式和一次性操作许可。账号角色分为全站系统管理员与空间角色，二者不混用。

腾讯云人机验证在服务端核验票据；发送邮件/短信验证码与注册/登录/找回密码按场景调用普通或无感验证。OAuth 账号不会因邮箱相同自动接管已有账号。重要配置仅在服务端使用并加密保存，读取接口不返回凭据明文。

私有文件需经应用授权读取。服务端应对用户输入、文件、外部服务响应和模型输出进行校验。审计日志避免记录密码、验证码、恢复码和服务密钥。

## 9. 页面适配与可访问性

界面提供中英文语言切换，并针对手机、平板和桌面采用响应式布局。窄屏下导航可操作，内容和表单纵向排布，图表保持可读，宽表格在容器内横向滚动。浏览器测试会检查多个视口的页面溢出、导航点击和认证控件触控面积。

## 10. 自动化验证

项目使用 Vitest 测试领域逻辑、API 约束、认证安全和组件行为；ESLint 与 TypeScript 检查静态问题；Next.js 生产构建检查发布包；Playwright 用于浏览器流程与响应式布局。

每次发布应记录实际运行的命令、结果、提交号和环境。自动化通过不证明外部模型精度、服务供应商持续可用、真实用户满意度或业务效果。

## 11. 部署与运行

生产部署需要 Node.js 运行环境、PostgreSQL、持久化 S3 兼容存储、HTTPS 反向代理、数据库迁移和受保护的服务配置。上传文件时排除 .env、私钥、Git 历史、依赖目录、构建缓存和数据库备份。构建成功并通过健康检查后再切换运行版本；数据库迁移需向后兼容并准备回滚策略。

## 12. 限制与后续方向

- 知识检索是轻量关键词排序，不具备向量检索和知识运营工作流。
- AI 自评置信度未经统计校准；异常输出需要人工复核。
- OCR 受图片清晰度、字体和版式影响。
- 当前没有以真实社团试点、用户研究或业务结果证明效果。
- 邮件、短信、AI、OAuth 和人机验证的实际可用性依赖线上配置与供应商状态。
- 可继续建立脱敏评测集，测量字段识别准确率和响应耗时，开展用户访谈，并在授权范围内评估试点。
