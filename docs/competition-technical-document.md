# CampusPulse AI 技术文档

## 1. 项目概述

CampusPulse AI 是面向高校学生、社团和管理人员的双语校园运营数据工作台。项目将表格数据、图片证据、AI 分析、图表、行动任务和报告交付连接成一条可追溯的业务流程。

项目的核心设计是：AI 输出必须与数据证据和工具调用关联，系统区分事实、推断和行动建议，避免把无法验证的生成内容当作运营结论。

## 2. 解决的问题

高校社团运营资料通常分散在表格、活动截图和历史报告中。传统方式需要手工整理字段、计算指标、寻找异常和编写复盘，协作成员也难以确认结论来源。

本项目解决四个问题：

- 统一接收 CSV、Excel 和图片资料。
- 通过 Agent 工具完成画像、聚合、异常检测和行动计划。
- 将分析结果转为图表、任务和双语报告。
- 通过空间权限、私有存储、认证和审计保护数据使用边界。

## 3. 主要功能

### 3.1 数据空间

用户可以导入 CSV、Excel 和图片。表格进入预览、字段识别和质量检查流程；图片进入 OCR 证据流程，识别出的表格会按行展开为结构化记录，字段字典、质量画像和统计都基于展开后的数据行，嵌套对象不会进入统计。系统会提示缺失值、重复行、异常候选和不支持的文件类型。

### 3.2 AI Agent

Agent 分析接口根据当前用户和工作空间权限读取数据，并使用结构化工具：

- 数据集画像与字段字典
- 指标聚合
- 异常检测
- 图表推荐
- 知识检索
- 行动计划生成
- 报告内容生成

返回结果带有工具调用、证据引用、置信度和语言信息。没有外部模型配置时，项目仍提供隔离的确定性演示路径，便于评审复现；生产环境会明确显示模型不可用或使用本地字段画像，不伪造模型结果。

### 3.3 图表与报告

图表画布支持 AI 推荐图表的一键导入、编辑、删除、保存和 PNG 导出。图表按数据集分别归属，切换数据集时只显示该数据集字段可支撑的图表，避免出现字段不存在的空图。报告中心支持双语报告生成、编辑、历史版本、Markdown/DOCX 下载和浏览器打印为 PDF。

### 3.4 协作与安全

项目支持个人空间和社团空间、成员邀请、角色权限、管理员空间、审计记录以及全站配置。登录与敏感账号操作可以使用邮箱、手机号、Authenticator 或一次性恢复码；验证码、人机验证、认证许可和会话版本由服务端校验。

## 4. 技术架构

- 前端：Next.js App Router、React、TypeScript、Tailwind CSS、ECharts、Animate.css。
- API：Next.js Route Handlers。
- 数据库：PostgreSQL + Prisma。
- 文件存储：S3 兼容私有对象存储。
- AI：OpenAI-compatible Chat Completions，支持结构化工具调用和 OCR 后处理。
- 认证：NextAuth、bcrypt、SMTP/短信验证码、RFC 6238 TOTP、一次性恢复码。
- 部署：Docker Compose，或通过 systemd 和 Nginx/宝塔运行。

### 4.1 数据流

1. 用户在工作空间内上传资料。
2. 服务端验证文件类型、大小、行数和列数。
3. 表格进入解析与质量检查；图片进入 OCR 证据流程，表格按行展开为结构化记录。
4. Agent 根据权限读取数据集和证据，调用确定性工具。
5. 系统返回事实、证据、置信度和建议。
6. 用户将结果保存为图表、行动任务或报告。

## 5. AI 设计与可追溯性

AI 不直接替代数据计算。报名数、签到数、转化率和异常候选由确定性工具计算，模型负责理解问题、组织工具调用和生成可读解释。

每条分析记录关联：

- 当前工作空间和数据集
- 使用的字段和工具
- 证据引用
- 模型与语言
- 置信度
- 事实、推断和建议的分层结果

演示数据为原创模拟数据，录制时不会展示真实学生信息或生产凭据。

## 6. 权限与隐私

数据集、原文件、分析、图表和报告都按工作空间授权。普通成员不能访问其他空间的数据；系统管理员拥有全站配置权限，但敏感值只显示脱敏结果。

生产凭据只通过环境变量或服务器配置提供，环境模板只保留占位符。公开仓库和比赛提交包不包含数据库、对象存储、SMTP、短信、AI、腾讯验证、OAuth、SSH 或管理员密码。

## 7. 可复现运行

环境要求：Node.js 22+、PostgreSQL、S3 兼容存储。

```bash
npm ci
cp .env.example .env
npm run db:generate
npx prisma migrate deploy
npm run dev
```

使用 Docker Compose：

```bash
docker compose up --build
```

访问 `http://localhost:3000`。生产环境必须关闭 `DEMO_AUTH_ENABLED`，配置随机会话密钥、数据库、私有存储和 AI 服务。

## 8. 质量验证

项目已配置：

```bash
npm run typecheck -- --incremental false
npm run lint
npm test
npm run build
npm run test:e2e
```

测试覆盖数据分析工具、API 合约、认证安全、权限隔离、响应式页面和生产构建。测试素材位于 `data/demo`，可用项目工具重新生成。

## 9. 竞赛演示路径

演示按照以下顺序进行：

1. 进入双语工作台。
2. 导入原创 CSV。
3. 查看字段质量和数据预览。
4. 提问“为什么 11 月签到下降？”
5. 展示 Agent 工具调用、证据和行动建议。
6. 将推荐导入图表画布并导出。
7. 生成中文和英文报告。
8. 展示权限、审计和安全设计。

## 10. 已知边界

GitHub OAuth 不在本次比赛版本中启用。AI 推荐仍需要团队复核；OCR、模型和外部服务不可用时，系统应显示明确的失败或降级状态。项目不把演示数据、模型生成内容或外部服务响应当作无需核验的真实运营结论。
