# 账号认证与平台配置

本文说明用户可见的认证流程及运行配置边界。真实凭据只放在服务器环境或经加密保存的平台配置中，不写入仓库。

## 权限角色

- 系统管理员：维护全站登录、注册、邮件、短信、验证码、AI 和导入配置，并管理平台用户与审计记录。
- 空间所有者/管理员：管理所属空间成员、数据和内容；不能读取全站服务密钥。
- 编辑者：在获授权的空间内维护数据与内容。
- 查看者：只读访问获授权的空间资源。

每个业务 API 都应在服务端重新验证账号、空间角色及目标资源归属；仅隐藏界面按钮不构成权限控制。

## 登录方式与验证码

系统可配置邮箱密码、邮箱验证码及手机验证码登录。短信可用性取决于管理员启用的供应商及模板配置；登录页面会依据服务端能力配置显示可用选项。

发送邮件或短信验证码前需要普通人机验证；注册、登录及密码找回等入口需要无感人机验证。验证码有有效期、重发间隔和尝试次数限制；通过后按场景单次消费。未配置供应商时，服务端明确返回不可用，不返回演示验证码或伪成功状态。

手机号码由统一国家/地区选择器规范化后校验。无效号码不会请求人机验证或调用短信供应商。默认选择的国家区号不作为额外提示文字显示。

### 邮件配置

初始环境变量为 SMTP_HOST、SMTP_PORT、SMTP_USER、SMTP_PASSWORD 和 SMTP_FROM。平台管理员也可在全站配置中心维护邮件服务并发送测试邮件。SMTP 服务接受邮件不等同于收件箱最终送达；请同时检查垃圾邮件目录。

SMTP 授权码属于密码凭据，不应使用邮箱网页登录密码替代。所有凭据只在服务端使用，读取接口不会回显明文。

### 短信配置

当前实现支持阿里云号码认证服务（PNVS）、互亿无线及自定义 HTTPS 网关适配。平台配置包括供应商、模板、签名、场景和凭据；实际可用范围以当前平台配置与供应商审核结果为准。

阿里云 PNVS 使用发送与校验 API 完成验证码生命周期。各业务场景可以分别配置模板：登录/注册、更新绑定号码、密码找回、新号码绑定及已绑定号码验证。模板必须与供应商控制台审核通过的内容一致。系统不在短信文案中拼入用户私钥或管理密码。

自定义网关必须调用真实供应商服务；仅在供应商明确接受时才能返回发送成功。公网接口需要限流、HTTPS 和服务端鉴权，不得把网关令牌暴露到浏览器。

## 敏感操作与双重验证

修改邮箱或手机号、更新密码、启用或关闭双重验证等操作使用统一身份验证窗口。用户只能选择当前已设置且可用的认证方式；验证通过后，服务端签发与账号、动作和目标绑定的一次性许可。

Microsoft Authenticator 可按 TOTP（RFC 6238）方式绑定。用户需在启用后保存一次性恢复码；认证码和恢复码均不可重复使用。管理员关闭“允许启用双重验证”只阻止新绑定，不会跳过现有用户的登录校验。

密码更新需要先完成身份验证，再输入并确认新密码；最终提交仍需新的人机验证。身份变更会提升认证版本并撤销旧会话。

## GitHub OAuth

系统管理员可在全站登录配置中设置 OAuth Client ID/Secret 和回调地址。未启用或未配置时，页面不提供 GitHub 登录入口。账号关联需由当前用户主动确认；仅邮箱相同不会自动接管已有账号。OAuth 应用的回调地址必须与实际部署域名和应用路径完全一致。

GitHub OAuth 是否适用于特定账号，受账号绑定状态、邮箱验证状态和账号安全策略限制。生产站点当前实际开放方式以登录页和平台配置为准。

## 加密与密钥轮换

邮件、短信、AI、OAuth 和人机验证凭据由服务端加密存储。用于派生加密密钥的会话密钥必须由部署环境保管并随密钥备份策略管理；直接更换可能导致现有加密配置或 TOTP 密钥无法解密。更换前应制定迁移、备份与回滚方案。

涉及 SMTP、短信、OAuth、AI 和人机验证的真实密钥不应放入 .env.example、截图、Git 历史或公开材料。
