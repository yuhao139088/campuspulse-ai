# 账号认证与系统配置

## 角色边界

- **系统管理员（User.globalRole=ADMIN）**：全站网站/登录/SMTP/SMS/AI/导入配置、用户平台角色、停用账号和撤销会话，查看所有空间、重命名和转移社团所有权。
- **空间所有者/管理员**：所属空间的成员邀请、角色、数据、审计和安全策略；无法读取或修改全站服务密钥。
- **编辑者**：所属空间的数据和内容写入。
- **查看者/指导教师**：所属空间只读访问。

入口为“管理员空间→平台管理→全站配置中心”。系统管理员可以在顶部选择任意空间。不能停用当前管理员账号或移除最后有效系统管理员。权限变更即时撤销该账号旧会话。

## 邮箱验证码

环境初始配置：`SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_FROM`。163邮箱使用 `smtp.163.com:465`，授权码由邮箱服务提供，不是网页邮箱登录密码。保存数据库配置后覆盖环境默认值。

后台“邮件服务”可调整SMTP服务器、端口、TLS、账号、发件地址与授权码，并向指定邮箱发送测试邮件。服务端确认SMTP服务器接受邮件后返回成功，收件箱到达仍取决于邮件供应商；请检查垃圾箱。

邮箱注册默认必须完成验证码。验证码10分钟有效、一次使用、每60秒重发一次，最多5次验证错误；重发会使之前的验证码失效。验证码使用服务端密钥散列存储，接口与审计不展示验证码。发送服务不可用时明确失败，不设置演示验证码。

## 手机接口与短信拓展

后台“短信服务”选择阿里云号码认证、互亿无线或自定义HTTPS网关，配置凭据与模板后启用短信和手机登录。手机号保存为E.164格式；大陆11位手机号码自动补 `+86`。

### 阿里云短信认证（PNVS）

使用官方 `@alicloud/dypnsapi20170525` SDK调用 `SendSmsVerifyCode` 和 `CheckSmsVerifyCode`，端点固定为 `dypnsapi.aliyuncs.com`。系统管理员配置AccessKey ID、加密AccessKey Secret、赠送签名、模板Code及认证场景前缀；云账号需具备这两个API的RAM权限，并开通短信认证服务。

默认模板100001使用 `{"code":"##code##","min":"10"}`，由阿里云生成6位数字码；实际有效期600秒，60秒发送间隔，重发覆盖旧验证码，不开启自动发送重试。注册、登录、绑定和找回密码使用独立SchemeName及随机OutId，避免跨用途使用。

| 操作用途 | 默认模板 | 触发方式 |
| --- | --- | --- |
| 登录/注册 | 100001 | 登录、注册和管理员单条测试 |
| 修改绑定手机号 | 100002 | 已绑定手机号的账号更换为新号码，场景由服务端判断 |
| 重置密码 | 100003 | 手机找回密码 |
| 绑定新手机号 | 100004 | 账号首次绑定手机号 |
| 验证绑定手机号 | 100005 | 个人设置验证当前账号已有号码，只允许本人操作 |

以上模板均可由系统管理员分别配置。手机号在登录/注册/找回密码、联系方式和短信测试区使用统一的圆角国家选择；默认不显示区号提示，提交时会组成E.164号码。服务商不支持的地区会禁用。发送前校验手机号长度与号段，前后端使用相同规则；无效输入不会启动人机验证或调用短信接口。格式有效后仍需验证码验证号码归属。

登录方式加载时不展示未配置短信的提示；登录/注册/找回密码和2FA表单使用主题内的行内错误、错误边框与聚焦，关闭浏览器原生必填提示。主身份验证成功后，开启2FA的账号仍进入独立认证码/恢复码窗口。

生成的码只在服务端暂时读取用于散列；数据库保存散列和场景/流水号，业务接口、日志与审计不返回明文码。用户正确输入后必须经云端核验 `Code=OK`、`Success=true` 且 `Model.VerifyResult=PASS`，再执行本地一次性消费；仅HTTP成功或OK不足以登录。主凭据预检通过后记录核验状态，以兼容独立2FA窗口，最终本地原子消费防止重放。管理员“发送测试短信”会发送一条并同时验证云端核验，确认运营商投递仍需收件人查收。

官方参考：阿里云帮助中心PNVS的SendSmsVerifyCode与CheckSmsVerifyCode API文档。原互亿无线和网关适配保留为管理员可选择的扩展。

互亿无线：配置APIID、APIKEY及模板ID（默认模板1），平台通过HTTPS POST表单向 `https://api.ihuyi.com/sms/Submit.json` 提交账号、密钥、11位手机号、验证码变量和templateid。只有返回code=2才认为已接受；失败时撤销验证码并报告供应商状态码。该适配器支持中国大陆手机号码，APIKEY加密保存且不回显。短信签名配置为供应商已审核的签名，模板方式由供应商匹配签名，不在验证码变量中重复拼接。系统管理员可填写手机号发送真实测试短信，供应商接受不等于运营商已投递。公开验证码接口继续要求腾讯普通人机验证。

网关是短信供应商适配接口，可以接入阿里云、腾讯云或其他短信商：

```http
POST https://your-sms-gateway.example/verification
Authorization: Bearer <gateway-token>
Content-Type: application/json
```

```json
{"phone":"+8613800138000","code":"123456","purpose":"register","template":"your-template-id","sign":"CampusPulse AI","expiresIn":600}
```

自定义网关只有在供应商已接受发送时才返回HTTP 2xx及 `{"ok":true}`；拒绝/超时应返回错误状态。网关自行签名并调用供应商官方API。此接口不能只是记录请求或返回伪成功。未配置真实供应商时，手机验证码发送、手机注册和OTP登录不可用。

| 接口 | 作用 |
| --- | --- |
| POST /api/auth/code | email/sms验证码；purpose为register/login/bind_email/bind_phone/reset_password |
| POST /api/auth/check | 人机验证及登录主凭据预检；不创建会话，返回是否需要2FA及一次性许可 |
| POST /api/auth/register | channel=email或sms；name、password、email/phone、code |
| POST /api/auth/callback/phone-otp | NextAuth手机OTP登录，需CSRF token；phone、code、totp |
| POST /api/auth/callback/credentials | 密码登录；email参数也可为已绑定手机号；password、totp |
| POST /api/auth/reset-password | 验证码重置密码；启用2FA时还必须验证第二因子 |
| GET /api/security/verify | 返回当前账号已绑定且可用的验证方式及脱敏地址 |
| POST /api/security/verify | stage=send通过普通人机验证发送旧联系方式验证码；stage=verify通过无感验证与身份因子签发动作许可 |
| GET/POST /api/security | 已登录账号状态、消费动作许可更新联系方式、密码和Authenticator设置 |

邮箱账号可在个人设置绑定手机号：先验证新号码，再在确认时通过已绑定方式验证当前身份。绑定/更换邮箱或手机、修改/找回密码、启用/关闭2FA和重新生成恢复码均撤销旧登录会话。

## 敏感操作验证窗口

个人设置不再要求输入当前密码。点击修改联系方式、更新密码、开启/关闭2FA或更新恢复码后，统一打开网站风格的身份验证窗口。只列当前账号已有的可用方式：邮箱、手机、已启用的Authenticator和剩余恢复码；邮件/短信服务尚未配置时不显示相应方式。新输入的联系方式不能作为当前身份验证方式。

发送验证码要求腾讯普通人机验证；确认身份要求腾讯无感验证，均在服务端检查。验证码发至账号当前绑定地址，10分钟有效，仅可使用一次，且绑定本次动作及账号。TOTP和恢复码同样防重放。

身份通过后签发5分钟一次性许可，绑定用户、认证版本、IP、动作及新联系方式；实际更新必须原子消费许可并进行认证版本条件更新。地址、操作、会话或IP改变后原许可不能复用。绑定新地址还须验证新地址验证码。

修改密码采用两阶段窗口：点击“更新密码”→验证已绑定身份→“设置新密码”窗口输入两次新密码。最终提交再次要求腾讯无感验证，服务端校验密码长度、动作许可及会话版本后更新。新密码最少8个字符、最多72个UTF-8字节；更新后重新登录。原页面没有新密码输入框，也不接受旧的密码直接授权接口。

## Microsoft Authenticator / TOTP

在“个人设置→账号与登录安全”点击绑定Authenticator，先在身份窗口选择已绑定方式验证；在微软应用中添加“其他账户”，扫描二维码，输入6位认证码确认。设备确认要求新的腾讯无感票据及与待绑定密钥关联的5分钟许可。兼容RFC6238 SHA1、6位、30秒的其他认证器。

密钥仅在初次绑定中展示，数据库使用AES-256-GCM加密。允许前后各一个30秒窗口，成功使用的时间步不能再次验证。手机和服务器需保持正确时间。

点击登录先校验人机验证及密码/手机验证码，再判断账号是否启用2FA；仅对已启用账号弹出独立窗口，可切换认证码或恢复码。登录及找回密码第二步确认也要求新的腾讯无感票据。已登录安全操作通过可选择已有方法的身份窗口；初次绑定设备确认只接受新认证器的6位码。

启用后所有密码和手机OTP登录均需TOTP或未使用恢复码；未完成第二因子不会发放登录会话。10个恢复码只在独立保存窗口显示一次，散列存储、每个限用一次；重新生成旧码全部失效。已登录用户可通过已有邮箱、手机或2FA方式完成安全操作，不需要当前密码。

管理员关闭“允许用户启用2FA”只暂停新绑定，已经启用的2FA继续验证。

## GitHub 授权登录

- 管理员在“系统配置 → 登录与注册”填写 GitHub OAuth App 的 Client ID 与 Client Secret 并打开开关；Client Secret 以 AES-256-GCM 加密后存库，界面只显示是否已配置。也可以改用环境变量 GITHUB_ID、GITHUB_SECRET，数据库配置优先。
- GitHub OAuth App 的 Authorization callback URL 必须填写站点地址加 /api/auth/callback/github，例如 https://cam.yuhaocloud.cn/api/auth/callback/github。
- 未配置或未开启时不注册 GitHub provider，/api/auth/features 返回 githubLogin:false，登录与注册页不显示 GitHub 按钮。
- 登录规则：GitHub 账号已关联则直接进入对应账号；邮箱已存在但未关联时拒绝登录，必须先在设置页关联，避免用未验证邮箱接管账号；邮箱不存在时按“允许公开注册”创建账号，并调用 GitHub /user/emails 确认该邮箱已验证。
- 已启用 2FA 的账号不允许 GitHub 登录或关联，避免 OAuth 绕过第二步验证。
- 设置页“GitHub 授权登录”支持关联与解绑：两者都先经过身份验证弹窗（仅可用账号已绑定的邮箱/手机/2FA）和腾讯人机验证；关联使用 10 分钟有效、HMAC 签名的一次性 Cookie 绑定当前登录用户，解绑会提升 authVersion 撤销全部会话，且必须保留密码或手机号等其他登录方式。
- 关联、登录、注册、授权与解绑都写入审计日志：account.github.link、account.github.signin、account.github.register、account.github.authorize、account.github.unlink。

## 密钥与配置维护

SMTP授权码、短信令牌和AI API密钥保存时加密，读取接口仅返回是否已配置；留空保留旧密钥。加密密钥由 `NEXTAUTH_SECRET` 派生。**必须连同数据库备份此环境密钥；直接更换会导致原加密配置和Authenticator密钥不能解密。**

全站配置变化、平台权限变化和账号安全变更始终记录审计。空间可关闭普通业务操作审计，成员/安全/平台操作仍保留。数据库连接、存储端点、服务端口和TLS证书由部署环境维护；迁移基础设施必须同时迁移现有数据和对象文件。
